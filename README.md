# newera · Theater

씬 안의 인물과 오브젝트가 사건을 관찰하고 각자의 다음 행동을 선택하는 텍스트 게임입니다. 세계관 아래에 씬과 원형을 정의하고, 실제 무대에는 독립적인 상태와 기억을 가진 인스턴스를 배치합니다. 동행 캐릭터는 플레이어와 씬을 이동하면서 같은 정체성과 기억을 유지합니다.

## 실행

Node.js 24.10 이상과 OEV 서버가 필요합니다.

```powershell
Copy-Item .env.example .env
npm install
npm run dev
```

`http://localhost:5173`에서 플레이하고 `/lores`에서 세계관·씬·원형·인스턴스를 편집합니다. 처음 실행하면 **비가 그친 뒤의 극장**이 열립니다. 새 예제는 `static/lore-presets/theater-opening.json`을 가져와 열 수 있습니다.

규모 있는 학원물 예제 **솔빛고, 가을제까지 열흘**은 [가져오기 파일](static/lore-presets/solbit-high.json)을 작업실에서 가져와 사용합니다. 현대 한국 고등학교를 배경으로 44개 씬, 학생·교직원·이웃 25명, 오브젝트 49개를 포함하며 일상·동아리·축제와 가벼운 미스터리를 다룹니다. [세계관·인물·단서 설정](docs/SOLBIT_HIGH.md)과 [작성 원본](lore-sources/solbit-high.json)을 함께 제공합니다.

```powershell
npm run build
npm start
```

개발 서버는 시작할 때 `.env`의 `NEWERA_` 설정을 읽습니다. 배포 실행은 `npm start`가 `.env`를 읽습니다. 직접 실행할 때는 `node --env-file-if-exists=.env build/index.js`를 사용합니다.

## 플레이와 편집

- **말하기**: 현재 씬의 한 인물 또는 현장 모두에게 말합니다. 다른 씬의 인물은 듣지 못합니다.
- **상호작용**: 씬에 있는 오브젝트의 현재 조건에 맞는 행동을 선택합니다. 선언된 효과가 상태를 바꾸고, 사건 반응 컴포넌트가 이어서 작동합니다.
- **이동**: 씬에 연결된 출구로 이동합니다. 동행은 같은 인스턴스로 따라오고, 현지 인물은 남습니다.
- **잠시 지켜본다**: 시간을 5분 진행하고 현장 인물들의 선택을 받습니다. 그 밖의 행동은 1분 진행합니다.

말을 건 상대가 먼저 판단하고, 말이나 행동이 확정되면 그것을 목격한 다른 현장 인물을 다시 판단 대기열에 넣습니다. 서연 → 하린의 질문 → 서연의 대답처럼 같은 인물이 여러 번 참여할 수 있습니다. 기다리기를 고른 인물도 새 사건이 생기면 다시 판단합니다. 기다림만으로 서로를 깨우지는 않으며 대기열이 비면 새 입력을 기다립니다. 인물끼리 대화하거나 오브젝트를 사용하거나 다른 씬으로 이동할 수 있고, 무대 밖 인물은 따로 시뮬레이션하지 않습니다.

생성 중에도 채팅으로 개입할 수 있습니다. 입력은 먼저 저장하고 다음 행동을 확정하기 전에 반영합니다. 이전 관찰로 생성하던 미확정 응답은 버리고 새 입력을 보고 다시 판단합니다. «그만»도 장면 안의 발언이므로 인물이 기다리거나 계속 말할지는 각자 결정합니다.

인물 한 명의 구조화된 응답을 검증할 때마다 행동·대사·메모를 저장하고 화면에 먼저 표시합니다. 다음 인물의 추론을 기다릴 필요가 없습니다. 화면은 생성 중 250ms 간격으로 진행 리비전을 확인하고 변경된 결과를 불러옵니다. 미완성 JSON이나 생성 중인 토큰은 표시하지 않습니다. 생성 상태에는 누적 판단 횟수와 대기 중인 인물 수를 표시합니다.

캐릭터는 신뢰도·호감도·친밀도·존중도·경계도와 상대별 인식·근거를 비공개 상태로 보유합니다. 새 사건을 목격하면 생성 모델이 관계·메모를 먼저 해석하고, 그 결과로 행동 여부를 판단합니다. 기다리기를 골라도 관계는 바뀔 수 있습니다. 같은 사건을 다시 평가하지 않도록 해석 위치도 함께 저장합니다. 공연 화면의 **세계관과 현재 인물의 기억 → 상대별 관계**에서 확인하고 편집 화면에서 현재 관계를 수정할 수 있습니다. 작업실의 **배치·관계** 탭에서 상대를 선택하고 슬라이더·미평가 옵션·일반 문장으로 현재 관계와 초기 관계를 각각 수정합니다. 초기 관계와 출력 계약은 [캐릭터 관계 문서](docs/CHARACTER_RELATIONSHIPS.md)에 정리했습니다.

**이 세션의 모델 설정**을 열면 OEV의 생성 가능 모델 목록에서 판단 모델과 생성 모델을 각각 선택할 수 있습니다. 선택은 현재 세계관에 저장되고 다음 진행부터 적용됩니다. 진행 중인 작업과 재시작 후 재개한 작업은 시작할 때 저장한 모델 ID를 유지합니다. **기본 설정 사용**으로 파일·환경 변수의 기본 모델로 돌아갈 수 있습니다. 이 선택은 진행 초기화·슬롯 불러오기에 영향을 받지 않으며, 다른 세계관의 선택과도 독립적입니다.

편집 화면은 **세계관 / 씬 / 캐릭터·사물 / 배치·관계 / 고급** 탭으로 나뉩니다. 기존 씬의 이름·설명·나가는 길과 캐릭터의 소개·성격·말투·목표를 카드에서 수정합니다. 상태는 이름·종류·값으로 입력하며 JSON을 직접 쓸 필요가 없습니다. 배치 카드는 **지금의 모습 / 이야기 시작 시점**을 나눠 현재 진행과 초기 설정을 각각 편집합니다. 상호작용·자동 반응과 전체 정의 JSON은 고급 편집으로 유지합니다. [작업실 사용 안내](docs/EDITOR_GUIDE.md)를 참고하세요.

진행은 세계관별로 자동 저장됩니다. 저장 슬롯 1~3은 세계관 정의와 현재 인스턴스·기억·사건을 함께 보관합니다. 세계관 내보내기에는 현재 진행과 슬롯이 포함되며, 공연 기록은 Markdown으로 내려받을 수 있습니다.

## OEV 설정

**세계관과 무대 편집 → 세계관 → 서술 문체 지침**에서 문장 길이·어휘·묘사 방식 등을 프롬프트로 지정할 수 있습니다. 행동·대사 생성에만 적용하며 캐릭터별 말투와 JSON 분리는 유지합니다. 빈칸으로 저장하면 기본 문체를 사용합니다.

플레이어와의 처음 관계는 최초 등장에 한 번, 인상착의는 최초 등장과 차림이 바뀐 뒤의 첫 등장에만 레이블 없는 문단으로 표시합니다. 과거 묘사는 당시 차림을 유지합니다. 작업실에서 외모·옷/음식 취향과 옷차림 후보를 편집합니다. 판단 모델은 첫 등장·날짜 변경, 또는 기본 180분 이상 지난 뒤 다른 씬에 등장할 때 옷을 다시 고를 수 있습니다. [인상착의와 저장 규칙](docs/CHARACTER_PRESENTATION.md)을 참고하세요.

API 명세는 [OEV 제공 문서](http://macstudio:12821/.skill)를 따릅니다. 클라이언트는 먼저 `/v1/models`에서 `task=generation` 모델을 확인합니다. 판단 기본 모델은 `gemma4-26b`이며 대사 모델을 비워두면 판단 모델과 같은 모델을 사용합니다.

| 설정 | 기본값 | 역할 |
| --- | --- | --- |
| `NEWERA_OEV_BASE_URL` | `http://macstudio:12821/v1` | 모델 검색·판단·대사 API |
| `NEWERA_DECISION_MODEL` | `gemma4-26b` | `/systemone` 판단 모델 |
| `NEWERA_TEXT_MODEL` | `gemma4-26b` (미지정 시 판단 모델과 동일) | `/chat/completions` 관찰·관계 해석과 상세 행동·대사·메모 생성 모델 |
| `NEWERA_DECISION_TIMEOUT_MS` | `30000` | 모델 검색·판단 요청별 대기 시간 |
| `NEWERA_LLM_TIMEOUT_MS` | `120000` | 구조화된 생성 요청별 대기 시간 |
| `NEWERA_MAX_OUTPUT_TOKENS` | `512` | 상세 행동 출력 토큰 한도 |
| `NEWERA_REFLECTION_MAX_OUTPUT_TOKENS` | `1024` | 관찰·관계 해석 출력 토큰 한도, 1~32768 |
| `NEWERA_MAX_RETRIES` | `2` | 실패한 호출의 추가 재시도 횟수, 0~5 (0이면 비활성화) |
| `NEWERA_RETRY_BASE_MS` | `1000` | 지수 백오프의 기본 대기 시간 |
| `NEWERA_RETRY_MAX_MS` | `8000` | 백오프 대기 시간의 상한 |
| `NEWERA_DATA_DIR` | `./data` | SQLite와 기본 모델 설정 파일 위치 |
| `NEWERA_MODEL_CONFIG` | `<data>/models.json` | 선택적인 실행 중 모델 설정 파일 |

`models.json`은 다음 진행을 시작할 때 다시 읽습니다. 파일이 환경 변수보다 우선하며, 수락한 진행은 설정 스냅샷을 유지합니다. 잘못된 파일은 경고를 남기고 마지막 유효 설정을 유지합니다. 최초 설정이 잘못되었으면 생성을 실패시킵니다.

```json
{
  "baseUrl": "http://macstudio:12821/v1",
  "decisionModel": "gemma4-26b",
  "textModel": "gemma4-26b",
  "decisionTimeoutMs": 30000,
  "timeoutMs": 120000,
  "maxOutputTokens": 512,
  "reflectionMaxOutputTokens": 1024,
  "maxRetries": 2,
  "retryBaseMs": 1000,
  "retryMaxMs": 8000
}
```

환경 변수와 `.env`, SQLite 위치를 변경하면 서버를 재시작해야 합니다. 환경 변수는 프로세스 시작 입력이고 SQLite 연결은 한 데이터 디렉터리에 묶여 있습니다.

일시적 HTTP 오류(408·429·500·502·503·504), 연결 실패·요청 시간 초과, 잘못된 판단·JSON·스키마·잘린 생성 결과는 해당 호출만 재시도합니다. 기본값은 최초 시도 후 최대 2회 추가하며 약 1초·2초를 기다립니다. 대기에는 ±20% 지터를 적용하고 최대 간격을 넘기지 않습니다. 설정·모델 선택 오류와 그 외 HTTP 오류는 즉시 실패하며, 장면 변경·실행권 상실·취소는 다음 요청을 막습니다. 성공한 판단이나 이미 확정된 행동은 다시 실행하지 않습니다. 생성 형식 검증은 재시도 때도 동일하게 적용합니다. 한도를 초과하면 시도 횟수와 오류를 표시합니다.

판단은 `/systemone`의 `participation` choice로 **참여한다(`act`) / 새로 참여하지 않는다(`wait`)**를 고릅니다. 같은 요청의 `inactivity` choice는 비참여일 때 **지켜본다(`watch`) / 하던 일을 계속한다(`continue`) / 아무것도 하지 않는다(`idle`)**를 구분합니다. `watch`만 지켜보는 행동을 기록하고, 뒤의 두 선택은 내부 상태만 저장하며 새 사건·대사·기억·작업 완료를 만들지 않습니다. 비참여는 상세 행동 생성을 생략하며 다른 사건이 생기면 다시 판단합니다. 그 전에 새 목격 사건이 있으면 생성 모델이 `character_reflection` 스키마로 관계·개인 메모를 해석합니다. 미처리 사건을 최대 16개씩 처리하며 새 사건이 없으면 해석 호출도 생략합니다. 행동할 때는 `/chat/completions`에 `response_format: json_schema`를 보내 실제 행동·대상·묘사·대사·개인 메모를 추론합니다. `actionId`는 현장에서 실행할 수 있는 모든 행동 ID 중에서 생성 모델이 선택하며, 대상과 효과는 실행기가 해당 ID로 확인합니다. 기존 `noul`·`score` 질문과 반응 임계값, 후보 묶음 판단은 사용하지 않습니다.

출력 필드는 `actionId`, `targetId`, `narrative`, `utterance`, `memoUpdate`입니다. 모델이 대상과 본문을 생성하면 실행기가 실제 행동 주체의 ID를 붙입니다. 대상은 선택한 행동의 대상과 일치해야 하며 모델이 `actorId`를 출력하는 것은 거부합니다. 말하기에는 대사가, 이동·상호작용에는 행동 묘사가 필요합니다. 메모 갱신은 자신의 요약·현재 의도·감정·미해결 문제 전체를 교체하고, null이면 기존 메모를 유지합니다. 다른 인물의 입력에는 이 메모를 전달하지 않습니다. JSON 파싱·필드와 길이·실행 가능성을 클라이언트에서도 검증하며, 알 수 없는 행동이나 임의 상태 수정, 잘린 출력은 실행하지 않습니다. 일반 문자열로 자동 전환하지 않습니다.

목격 기억은 `actorId`(주체), `targetId`(대상), `kind`(사건 종류), `body.narrative`(행동), `body.utterance`(발언)를 가진 JSON으로 저장·전달합니다. 플레이어의 행동을 NPC 기억에 `나:`라는 문장으로 쓰지 않습니다. 기존 문자열 기억은 연결된 사건 ID에서 주체와 본문을 복원하고, 원래 사건을 찾을 수 없는 문자열은 보존하되 모델에게 주체를 추측시켜 전달하지 않습니다.

이 기반에서는 개인의 최근 목격 기억을 사용하며 임베딩 서버를 호출하지 않습니다. 캐릭터가 없는 씬은 모델 연결 없이 진행할 수 있습니다. 플레이어 입력과 각 인물의 결과는 순서대로 확정합니다. 이후 모델이나 검증에 실패해도 앞서 확정한 결과는 유지하며 실패한 결과만 적용하지 않습니다. 실행 중 서버가 재시작되면 저장된 반응 대기열과 채팅 소비 위치에서 이어가므로 입력이나 완료된 행동을 중복 적용하지 않습니다. 이후의 새로운 사건으로 같은 인물을 다시 판단하는 것은 별도의 반응입니다.

## 데이터 형식

씬 기반 `newera-theater` version 2만 사용합니다. 세계관·진행·저장 슬롯·생성 작업은 `data/newera.sqlite`의 `theater_*` 테이블에 저장합니다. 구형 형식의 가져오기와 자동 이전은 지원하지 않습니다.
