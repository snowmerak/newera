# newera 진행 구조

newera는 era의 수치와 행동 규칙을 이어받되, 읽고 선택하는 텍스트 게임이다. 화면에는 장면과 선택이 먼저 나온다. 세계와 등장인물은 플레이어의 행동을 기다리기만 하지 않는다.

## 한 턴

1. 플레이어가 `다음 장면`을 누르거나, 현재 상대에 맞는 LLM 행동 제안을 받아 선택하거나, 행동을 자유롭게 입력한다. 제안을 만드는 것만으로는 턴이 진행되지 않는다.
2. **세계 담당 LLM**이 세계관, 시간·장소, 최근 확정 사건, 등장인물 설정을 받아 외부 상황과 다음 장면의 초입을 만든다. 플레이어가 행동을 골랐다면 그 결과를 미리 결정하지 않는다.
3. 세계가 주목한 인물의 **인물 담당 LLM**이 자기 설정, BASE·TRAIT·ABL·EXP·MARK·RELATION·PALAM, 자기 기억을 받아 행동한다. 플레이어의 제안에 반응하거나 먼저 행동을 제안할 수 있다. 호출마다 새로운 요청이지만 저장된 인물 정보와 기억으로 맥락을 복원한다. 세계 담당은 별도의 지속 요약과 최근 사건으로 흐름을 잇는다.
4. 자유 입력은 LLM이 기존 COMMAND 해당 여부와 대상을 먼저 해석한다. 해당하면 잠긴 조건을 그대로 검사하고, 수락되어 실제로 일어난 행동만 SOURCE·PALAM·관계·경험·MARK 계산에 반영한다. 다른 자유 행동은 장면과 사건으로 진행하며 지금은 수치를 임의로 만들지 않는다. 제안과 거절도 실행된 행동으로 계산하지 않는다.
5. 장면과 확정 사건을 기록한다. 인물 세션이 이후 행동에 영향을 줄 구체적 사실을 남겼을 때만 별도의 짧은 기억을 저장한다. 장면의 수식적인 문장은 기억 검색이나 다음 프롬프트에 다시 넣지 않는다.

세계 담당과 인물 담당은 같은 LM Studio 채팅 모델을 별도 프롬프트와 입력으로 호출한다. 지금은 한 장면에서 세계가 선택한 인물 한 명을 호출한다. 인물마다 독립된 기억이 있고, 여러 인물이 동시에 대화하는 장면이나 인물 간 상호작용은 이후 확장할 부분이다.

## 설정과 저장

메인 `/`은 플레이 화면이다. 왼쪽 사이드바 위에는 로어 제목을 나열하고 아래에는 선택한 로어의 저장 슬롯 1~3을 배치한다. 본문에는 현재 플레이 중인 로어의 장면과 자동 저장되는 현재 세션을 표시한다. `/lores`는 로어 관리 화면으로 생성, 제목·세계관·era 규칙·인물 원본 편집, 삭제, JSON 가져오기·내보내기를 제공한다. 인물 원본의 초기 수치와 현재 세션의 진행 수치는 별도 테이블에 둔다. 원본의 수치를 고쳐도 현재 세션의 BASE·TALENT·ABL·EXP·RELATION·PALAM·MARK는 변하지 않는다. 이름·설정·TRAIT와 행동 조건은 원본 설정이므로 현재 세션에도 반영한다. 세계 상태, 설정, 인물, 제안, 사건, 기억은 로어별로 SQLite에 남는다. 새 로어는 빈 인물 목록과 별도의 진행으로 시작하고, 이전 버전의 데이터와 슬롯은 첫 로어에 보존한다. 로어 JSON 내보내기에는 원본 설정, 현재 진행과 저장 슬롯이 포함된다.

행동 선행 조건은 인물별 가변 목록이다. 각 행은 `행동 · 수치 경로 · 최소값`으로 구성하며 로어 화면에서 추가하거나 삭제한다. 조건이 하나도 없는 행동은 관계나 경험 수치 때문에 잠기지 않는다. 입맞춤 같은 특정 MARK를 친밀 행동의 공통 선행 조건으로 강제하지 않는다. 대상 선택과 성인 여부는 행동 시스템의 공통 조건으로 유지한다.

`/simulator`는 현재 로어의 인물 상태를 사용하는 결정적 수직 슬라이스다. 순수 함수로 상황과 행동 조건을 검사하고 `대화한다`의 SOURCE를 계산한다. 대상 TALENT·ABL·RELATION·현재 PALAM에 따라 효과가 달라지며 PALAM·EXP·RELATION·MARK를 갱신한다. 구조화된 SemanticEvent에서 별도 템플릿 renderer가 문장을 만든다. 서버는 상태와 사건 기록을 같은 SQLite 트랜잭션으로 저장하며, 결과는 기존 플레이 화면과 저장 슬롯에 반영된다. 이 행동은 LLM을 호출하지 않는다.

수치의 시간축을 분리한다. BASE는 등장인물의 자원, TALENT는 비교적 고정된 성향, ABL은 성장 가능한 능력, EXP는 누적 경험이다. 플레이어에게는 체력 수치나 행동 체력 비용이 없다. `잠시 쉰다`는 시간과 장면을 진행한다. RELATION은 `인물 ID → 대상 ID`의 방향을 갖는 장기 관계로, 현재 편집 화면은 플레이어를 대상으로 한 값을 다룬다. PALAM은 장면의 반응이며 이동·휴식·세계 대기·긴 시간 경과에 새 장면으로 초기화된다. SOURCE는 한 번의 행동 효과이고 저장 상태가 아니다. 기존 저장의 단일 관계는 `player` 대상 관계로, 옛 대화·공감 경험은 사회 경험으로, 장면 신뢰는 편안함으로 변환한다. 옛 플레이어 체력은 불러올 때 무시하고 새 저장에는 포함하지 않는다. 이미 기록한 사건은 당시 규칙의 기록으로 유지한다.

JSON 모듈을 선택한 로어에 설치하면 세계관 또는 성인 등장인물을 적용할 수 있다. 세계관 모듈은 한 번에 하나만 활성화하며 기본 세계관 설명을 대체한다. 모듈 규칙은 기본 era 규칙에 추가된다. 인물 전용 모듈은 여러 개를 동시에 적용할 수 있고, 모듈을 꺼도 해당 인물의 스탯·사건·기억은 지우지 않는다. 저장 슬롯에는 활성 모듈 ID가 포함되며 슬롯을 불러와도 이후 설치한 모듈 파일은 지우지 않는다. 파일 형식과 예시는 [모듈 안내](../static/modules/README.md)에 있다. 현재 모듈은 세계관 설명과 인물 데이터를 제공하며, COMMAND의 계산식을 추가하거나 바꾸는 기능은 포함하지 않는다.

기억은 SQLite FTS5 trigram/BM25와 임베딩 코사인 유사도를 함께 검색한다. 임베딩 서버가 응답하지 않아도 최근 기억과 BM25 검색으로 장면을 계속 만들 수 있다. 세계 또는 인물 채팅 모델이 응답하지 않으면 해당 턴은 기록하지 않고 오류를 보여준다.

이전 버전이 `사건 요약 + 장면 전체`를 기억으로 저장한 항목은 읽을 때 사건 요약만 사용한다. 저장된 원본과 슬롯은 수정하지 않는다. 화면의 기억 목록은 새 방식의 구체적 기억만 보여주고, 이전 턴은 행동 기록에서 확인할 수 있다.

기본 모델 서버는 `http://localhost:1234/v1`이며 채팅 모델은 `gemma4-26b-a4b-qat-uncensored-hauhaucs-balanced-mtp`, 임베딩 모델은 `text-embedding-qwen3-embedding-0.6b`다. 채팅 요청에 `max_tokens`를 지정하지 않는다.

현재 수치·행동 목록은 작은 예시다. 행동별 대사와 인물 고유의 일정, 다인 장면, 세계 규칙을 실제 계산식으로 확장하는 작업은 남아 있다. 입력한 era 규칙 텍스트는 현재 LLM의 판단 자료이며, 코드의 행동 조건과 수치 계산식을 자동으로 변경하지는 않는다.
