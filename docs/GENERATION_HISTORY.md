# 생성 전용 히스토리

행동·대사 생성은 각 인물이 목격한 확정된 기록을 이어받아 다음 행동 하나를 만드는 방식으로 진행한다. 기존 반응 루프가 새 행동을 확정하면 다음 생성 호출의 히스토리에 포함된다. 거절되거나 실패한 모델 제안, 미완성 출력, 비공개 추론은 히스토리에 추가하지 않는다.

## 범위와 예산

- 대상은 `actor_performance` 생성 호출이다. 참여·비참여·옷차림·정체성/행동 검수의 typed decision과 새 사건의 관계 해석에는 적용하지 않는다.
- `history`에는 해당 인물이 실제 목격한 대화·행동·씬 출발/도착·상태 변화만 원래 사건 순서로 넣는다. 다른 씬의 미목격 사건과 다른 인물의 비공개 메모는 전달하지 않는다.
- 주체/대상 ID·이름, 장소 ID·이름, 사건 ID·tick, 행동/발언과 효과를 보존한다. 순서는 tick만으로 재정렬하지 않고 확정된 사건 배열을 따른다.
- 기본 예산은 **32768 추정 토큰**이다. 히스토리 JSON의 UTF-8 바이트 수를 3으로 나눈 뒤 올림해서 추정한다. JSON 메타데이터·이름·배열 구분자도 포함한다. 모델별 토크나이저를 사용한 정확한 토큰 수는 아니므로 실제 입력 토큰과 차이가 날 수 있다.
- 가장 최근 사건부터 거꾸로 계산해서 예산 안에 드는 연속 구간을 선택하고, 전달 순서는 오래된 것부터 유지한다. 원문 문장 중간을 자르거나 오래된 사건을 임의로 끼워 넣지 않는다.
- 최신 사건 하나가 한도를 초과하면 그 사건을 숨기는 대신 명시적으로 실패한다. 예산을 늘려 재시도할 수 있다.
- 세계관 규칙·정체성·성격·현재 상태/메모·현재 장소·현장 인물·문체·행동 후보·출력 스키마와 출력 토큰은 이 예산 밖이다. **전체 요청을 32K로 제한하는 설정은 아니다.**

생성 입력에서는 기존 `recentEvents`와 `recalledEvents`를 별도로 반복하지 않는다. 판단과 검수는 기존의 짧은 최근 기록·LanceDB 회상을 유지한다. 생성 히스토리는 현재 세계관의 원본에서 다시 구성하므로 슬롯 불러오기·초기화·복구 후 폐기된 사건을 이어 붙이지 않는다.

SQLite의 사건과 캐릭터 기억은 삭제하지 않는다. 잘려서 생성에 전달되지 않은 과거 기록은 저장·내보내기·장기기억 검색에 남는다. `historyWindow`와 서버의 `[생성 히스토리] 입력 구성` 로그에 한도·추정 토큰·생략 개수·잘림 여부를 기록한다. 대화 본문은 로그에 남기지 않는다.

## 설정

환경 변수는 `NEWERA_GENERATION_HISTORY_TOKENS=32768`이다. 기존 모델 설정 파일에서는 다음 항목을 쓴다.

```json
{
  "generationHistoryTokens": 32768
}
```

허용 범위는 256~131072의 정수다. 파일이 환경 변수보다 우선하며 다음 Director 연결에서 다시 읽는다. 이미 연결된 작업은 기존 스냅샷을 유지한다. 파일의 잘못된 값은 마지막 유효 설정으로 돌아간다. 환경 변수·`.env`를 바꾸면 서버를 재시작한다.

자동 검증은 목격 범위·이동 기록·사건 순서·UTF-8 예산·과거부터 제거·원본 보존·복원·생성 요청의 실제 잘림·typed 입력 불변·설정 재읽기를 확인한다. 이 기능은 히스토리 관리이며 별도의 대화 프레임이나 도구 실행 프로토콜을 새로 도입하지 않는다.
