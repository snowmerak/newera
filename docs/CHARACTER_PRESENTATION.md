# 인물 소개·취향·인상착의

공연 화면의 **현재 등장인물 소개**를 펼치면 플레이어와의 처음 설정, 현재 인상착의를 확인할 수 있다. 최근 100개 사건 중 해당 인물의 첫 사건 앞에도 소개를 붙인다. 인상착의는 **현재 상태**이며 과거 사건 당시의 복장 기록으로 해석하지 않는다. 소개 때문에 가짜 행동·발언이나 기억을 추가하지 않는다.

## 공개 설정과 개인 취향

| 위치 | 필드 | 의미 |
| --- | --- | --- |
| `definition.templates[]` | `baseAppearance` | 머리·안경 등 기본 외모, 최대 400자 |
| 같은 위치 | `clothingPreferences`, `foodPreferences` | 인물 자신의 옷·음식 취향, 각각 최대 1200자 |
| 같은 위치 | `wardrobe[]` | 미리 작성한 옷차림 후보, 최대 36개 |
| `definition.spawns[]`, `state.instances[]` | `playerContext` | 플레이어가 아는 초기 관계, 최대 1200자 |
| 같은 위치 | `appearance` | 현재 보이는 외모와 옷차림, 최대 1200자 |
| `state.instances[]` | `appearanceSelection` | 마지막 선택의 일차·시각·씬·후보 ID·판단 모델 |

`playerContext`는 “오늘 안내를 맡은 같은 반 학생, 오늘 처음 만남”처럼 공개된 시작 관계다. 현재 호감·신뢰나 상대의 비밀을 담지 않는다. 관계 수치·인식·동적 메모는 기존 비공개 상태로 따로 유지한다.

자기 관찰 입력에는 자신의 취향을 넣고, 다른 인물을 관찰할 때는 현재 `appearance`만 전달한다. 타인의 취향·메모·관계·초기 플레이어 설정을 자동 공유하지 않는다. 취향은 선택과 대사의 참고이며 음식 구매·섭취·소지품·알레르기를 확정하는 기능이 아니다.

## 옷차림 선택

후보 예시:

```json
{
  "baseAppearance": "단정한 단발에 노란 실핀을 꽂았다.",
  "clothingPreferences": "밝은 가디건과 편한 운동화를 좋아한다.",
  "foodPreferences": "달걀 샌드위치와 귤을 좋아한다.",
  "wardrobe": [
    { "id": "uniform", "name": "교복", "appearance": "교복 위에 연노랑 가디건을 걸쳤다.", "context": "등교일의 수업과 방과후 안내." },
    { "id": "casual", "name": "휴일 차림", "appearance": "크림색 맨투맨과 청바지를 입었다.", "context": "수업 없는 날의 외출." }
  ]
}
```

플레이어가 진행을 요청해 현장 인물들이 판단하기 전에, 선택이 필요한 모든 현장 인물의 옷차림을 먼저 확정한다. 선택 조건은 다음과 같다.

1. 아직 선택 기록이 없는 첫 등장.
2. 마지막 선택과 현재 일차가 다름.
3. 같은 날이라도 **마지막 선택 장소와 현재 씬이 다르고**, 마지막 선택 이후 `definition.appearanceChangeMinutes` 이상 지남.

간격은 기본 **180분**, 세계관 탭에서 **1~1440분**으로 수정한다. 18:00 로비에서 고른 뒤 18:10 교실에 들어가면 유지한다. 21:00 다른 씬에 있으면 다시 선택할 수 있다. 같은 씬에 계속 머물면 시간이 지나도 유지하며, 다음 날에는 같은 씬에서도 다시 선택한다. 시각은 게임 내 `state.day`/`state.minute` 기준이다. 이번 변경은 기존 시간 진행 규칙을 바꾸지 않는다.

선택은 세션의 **판단 모델**을 사용하는 `/systemone`의 별도 `outfit` choice 질문이다. 현재 씬·시각·자기 취향·이전 옷차림과 각 후보의 맥락을 보며, 옷을 바꿀 이유가 없으면 이전 후보를 다시 선택할 수 있다. 참여 여부의 `act`/`wait` 질문은 그대로 유지한다. 상세 행동·발언은 기존 JSON 스키마 생성으로 받는다.

호스트는 후보 ID를 검증한 뒤 `baseAppearance + 선택 후보.appearance`를 현재 인상착의로 저장한다. 모델은 없는 옷을 만들거나 옷 선택으로 하지 않은 활동을 완료할 수 없다. 후보가 비어 있으면 선택 호출을 하지 않고 수동 인상착의를 유지한다. 초기 배치의 `appearance`는 첫 선택 전에도 보여줄 수 있는 기본 모습이다. 화면을 여는 것만으로 모델을 호출하지는 않는다.

## 저장과 편집

선택 결과와 시각·장소를 다음 추론 **전에** 저장한다. 뒤의 관계 해석·행동 생성이 실패하거나 서버가 재시작되어도 이미 선택한 모습은 유지한다. 재시도는 실패한 호출에만 적용한다. 선택 도중 새 채팅이 들어오면 미확정 결과를 버리고 새 관찰로 다시 고른다. 선택만으로 사건·기억·시간을 늘리거나 다른 캐릭터를 깨우지 않는다.

작업실 **캐릭터·사물**에서 기본 외모, 옷·음식 취향, 후보의 이름·차림·착용 맥락을 일반 입력으로 편집한다. **배치·관계**에서는 플레이어와의 처음 설정과 현재 인상착의를 수정한다. 현재 외모를 수동으로 바꾸면 현재 일차·시각·장소와 `model: "manual"`, `outfitId: null`을 저장해 바로 덮어쓰지 않는다. 이후 날짜/장소·시간 조건을 충족하면 후보 중 다시 선택할 수 있다. 초기 배치 편집은 현재 진행에 적용하지 않는다.

필드는 모두 선택 사항이다. 기존 JSON v2와 저장 슬롯을 계속 읽을 수 있고, 새 필드가 없는 폼으로 다른 항목을 수정해도 취향·소개를 지우지 않는다. 일차만 있는 이전 선택 기록은 같은 날 유지하고 다음 날 다시 고른다. 슬롯·내보내기는 인상착의와 선택 기록을 함께 보존한다.

솔빛고 프리셋에는 25명 모두 공개 시작 관계·기본 외모·옷/음식 취향과 옷차림 후보 3개씩을 넣었다. 학생들의 교복·동아리 작업복·휴일 차림, 성인들의 근무복·업무별 차림·휴일 차림을 구분했다.
