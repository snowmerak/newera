# LanceDB 장기기억 검색

Node 프로세스 안의 `@lancedb/lancedb` 0.40과 연결된 OEV의 `embeddinggemma2`를 사용한다. 원본 사건·목격 범위·캐릭터 메모는 기존 SQLite에 유지하며 LanceDB는 지워도 다시 만들 수 있는 검색 자료다. 별도 검색 서버나 로컬 임베딩 모델을 실행하지 않는다.

## 현재 동작

1. 참여 판단 직전, 해당 캐릭터가 목격한 사건 중 최근 기억 16개 밖에 있는 말·행동이 있는지 확인한다. 없으면 검색·임베딩 요청을 생략한다.
2. 세계관의 현재 원본 사건과 목격자 목록을 색인과 비교한다. 새 사건·내용/목격 범위 변경은 반영하고 현재 원본에서 사라진 사건은 제거한다. 기다리기 기록과 연결할 원본이 없는 옛 문자열 기억은 색인하지 않는다.
3. 최근 사건 2개의 본문, 자기 현재 의도, 현재 장소로 검색 단서를 만든다. 1200자 이내로 제한하며 세계관 전문과 다른 사람의 비공개 메모는 넣지 않는다.
4. 세계관별 테이블과 `witnesses` 필터로 범위를 먼저 제한한다. 최근 기억 16개도 검색 후보에서 제외한다. BM25와 코사인 벡터 검색 결과를 RRF로 결합한다. 현재는 소규모 데이터에 정확한 벡터 검색을 사용하며 ANN 색인을 학습하지 않는다.
5. 반환된 ID와 내용 해시를 현재 SQLite 스냅샷과 다시 대조하고 원본 구조화 사건으로 복원한다. 기본 4개·UTF-8 JSON 6000바이트 이내에서 **사건 전체**를 선택하며 중간 발언을 잘라서 사실처럼 전달하지 않는다.
6. 참여 판단에는 최대 2개, 검수에는 선택한 결과 전체를 별도 `recalledEvents`에 넣는다. 실제 주체·대상 ID와 이름을 함께 전달한다. 같은 관찰 객체의 판단·생성은 한 번 조회한 결과를 재사용한다. 상세 행동·대사 생성에는 별도의 [약 32K 생성 히스토리](GENERATION_HISTORY.md)를 사용하며 같은 사건을 검색 결과로 중복 추가하지 않는다.

최근 사건을 지우거나 회상한 사건을 새 사건으로 재실행하지 않는다. 옷차림 판단·비참여 태도 판단·새 목격 사건의 관계 해석에는 검색 결과를 추가하지 않는다. 과거 사건을 다시 평가해서 관계 수치가 올라가는 것을 막기 위한 경계다.

## 한국어와 임베딩

기본 토크나이저는 사전 없이 동작하는 `ngram`이며 2~3자 부분 문자열을 색인·질의에 동일하게 적용한다. `교실` 질의로 `교실로`가 포함된 기록을 찾는 것을 실제 Windows LanceDB로 검증했다. 형태소 분석은 아니므로 짧은 공통 문자열이 불필요하게 일치할 수 있다.

`memoryTokenizer: "lindera/ko-dic"`으로 한국어 형태소 토크나이저를 선택할 수 있다. 이 경우 Lance가 읽을 수 있게 컴파일된 Ko-dic 사전을 `<LANCE_LANGUAGE_MODEL_HOME>/lindera/ko-dic`에 먼저 설치해야 한다. 환경 변수가 없으면 Lance의 플랫폼 기본 모델 디렉터리를 사용한다. 현재 개발 환경에는 사전이 없으며 이 경로의 검색 품질은 검증하지 않았다. 사전 누락을 다른 토크나이저로 몰래 대체하지 않고 검색 실패로 기록한다.

임베딩은 `/v1/embeddings`에 `input_type: query`와 `document`를 구분해서 요청한다. 서버가 모델별 검색 프롬프트를 적용하므로 클라이언트에서 접두사를 중복해서 붙이지 않는다. 기본 모델과 차원은 `embeddinggemma2`·768이다.

- 배치는 최대 8개·입력 UTF-8 합계 12000바이트로 제한한다. 한 문서는 최대 6000바이트다. 바이트 예산은 한국어 글자 수로 토큰을 추측하지 않고 입력을 보수적으로 제한하는 운영 정책이며, 서버의 실제 토큰 예산을 대체하지 않는다.
- 긴 가져오기 기록은 잘라내지 않고 색인 대상에서 제외하며 로그에 개수를 남긴다. 원본과 최근 관찰 기록은 유지된다.
- 응답 모델·개수·고유 index·차원·유한한 Float32 값·영벡터 여부를 검증한 뒤 배치 전체를 저장한다. 순서가 바뀌어도 index로 매핑하고 잘못된 응답은 벡터를 완료 처리하지 않는다.
- 조회당 최대 32개 문서의 벡터를 보충한다. BM25에는 현재 사건 전체가 먼저 반영되며 벡터가 아직 없는 나머지는 이후 조회에서 처리한다. 로그의 `vectorBacklog`로 잔여 개수를 확인한다.
- 서버 재시작 후 이미 저장한 벡터를 재사용한다. 질의 벡터는 조회마다 생성한다. 기본 대기 시간은 요청당 10초, 임베딩 추가 재시도는 최대 1회이며 기존 백오프 정책을 따른다.

## 장애와 저장 복원

`memorySearch.status`는 `hybrid`, `bm25`, `unavailable`, `disabled`, `not_needed`로 구분한다. 임베딩·벡터 검색 실패는 BM25로 진행한다. LanceDB·FTS 실패는 최근 사건과 현재 메모를 유지하고 `unavailable`로 전달한다. 어느 경우에도 검색 장애를 기억 자체가 없다는 사실로 취급하지 않는다. 운영 중단 신호와 작업 소유권 상실은 이 대체 경로로 삼키지 않는다.

테이블 이름에는 세계관 ID·서버 주소·모델 ID·차원·토크나이저·텍스트 구성 버전의 해시가 들어간다. 다른 모델이나 토크나이저의 벡터를 섞지 않는다. 같은 모델 ID의 실제 모델 내용이 바뀌면 새 별칭을 사용하거나 색인을 다시 만들어야 한다.

슬롯 복원·진행 초기화·세계관 교체·수동 기록 복구 뒤에도 다음 검색에서 현재 원본과 재비교한다. 검색이 필요 없는 동안에는 옛 색인 파일이 남을 수 있지만 현재 목격 기록에 없는 사건을 모델에 돌려주지 않는다. 삭제한 세계관이나 바뀐 모델의 미사용 테이블은 디스크에 남을 수 있다. 앱을 중단한 뒤 **LanceDB 색인 디렉터리만** 삭제하면 다음 필요한 조회에서 다시 생성된다. SQLite 파일을 삭제할 필요는 없다.

색인은 슬롯·내보내기에 포함하지 않는다. 가져온 세계관은 저장된 사건과 실제 목격 범위로 재구성한다. 이 기능은 과거 사건 검색이며, 대화 프레임·미응답 질문·현재 과제의 별도 상태 저장은 아직 구현하지 않았다.

## 설정

설정 파일은 기존 `NEWERA_MODEL_CONFIG` 또는 `<NEWERA_DATA_DIR>/models.json`을 사용한다. 파일 항목이 환경 변수보다 우선한다.

```json
{
  "memoryEnabled": true,
  "embeddingModel": "embeddinggemma2",
  "embeddingDimensions": 768,
  "embeddingTimeoutMs": 10000,
  "memoryTokenizer": "ngram",
  "memoryTopK": 4,
  "memoryMaxBytes": 6000
}
```

파일은 다음 작업을 시작할 때 다시 읽는다. 실행 중인 작업의 검색기는 생성 시점 설정을 유지하며 재시작 후 재개한 작업은 그때의 검색 설정을 사용한다. 잘못된 설정은 마지막 유효 설정을 유지한다. 최초 설정부터 잘못된 경우에는 작업 시작을 실패시킨다. 모델·차원·토크나이저 변경은 별도 색인을 사용하므로 서버 재시작 없이 다음 작업부터 적용한다.

환경 변수 이름·범위는 [README의 설정 표](../README.md#oev-설정)에 정리했다. `NEWERA_MEMORY_DIR`은 기본 `<data>/memory-lance`이며 환경 변수·사전 경로를 바꾸려면 서버를 재시작한다. `.env`의 수정은 실행 중인 프로세스에 자동으로 반영되지 않는다.

## 확인한 범위

- 실제 Windows LanceDB: 한국어 부분 문자열 BM25, 벡터 순위 결합, 세계관·목격자 격리, 원본 변경·복원, 디스크 벡터 재사용, 바이트 예산, 장애와 취소.
- 빌드한 앱: 오래된 우산 기록이 실제 worker → OEV 판단·생성 입력으로 전달되고 원본 사건이 중복 실행되지 않음.
- 실제 OEV: `embeddinggemma2`·768차원 query/document 요청 → 임시 LanceDB → 과거 우산 사건 우선 검색, 미목격 비밀 기록 제외. 실제 게임 진행은 변경하지 않음.

대규모 기록의 성능과 실제 대화에서의 장기적인 검색 품질은 별도 측정 대상이다.
